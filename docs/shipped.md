# Shipped Today

This page inventories behavior implemented in this source tree, developed and
installed from master. Add or update rows with the change that implements the
behavior. An installed executable may temporarily lag this source revision;
this page does not inventory whichever binary is on a host's PATH. It excludes
planned, target, and deferred capabilities; those belong in the
[roadmap](roadmap.md), not in this table.

| Landing record | `done --landed COMMIT --remote R --branch B --pushed-at T [--installed-build F]` (MCP `landing`) records in the seal where the completed work landed, as asserted provenance: the commit (40 or 64 lowercase hex), remote, branch, push time and, when a binary was installed, its build fingerprint. The landing flags are all or nothing, and a malformed landing is refused before anything is recorded. Remote and branch must be plain git ref names, never revision expressions such as `master~5` or `master@{1}`. Completed `show` and `show --json` give it as one `landing` field, with the installed build in full beside "asserted, unchecked" (`installed_build_assurance`), or "no installed build recorded", derived when read so old seals read alike; the value is never compared with any build, and its full value comes from the installed executable's own `readiness --json` or `doctor --json`, never completed by hand from a shortened one; a seal without one reads "no landing recorded", and a seal that could not be read, or a completion restored from history, reads "unavailable (REASON)". The `done` receipt echoes a landing when one was named, and a replayed receipt whose seal cannot be read says the landing is unavailable. The landing is part of `done`'s intent: repeating the same `done` reads the frozen seal back, landing included, while naming a landing the seal does not already record is refused as a late finding on completed work. Historical seals carry none and are read as stored; their landings, and landings made after `done`, stay in prose landing notes. On request only, `doctor --check-landings [--repo PATH]` prints each landing's installed build the same way, apart from its Git verdict, and checks that each recorded commit exists locally under exactly its recorded id (not a prefix of a longer id, nor a tag that peels to it) and lies on the named remote branch's exact remote-tracking ref (a local branch or tag spelling that name does not count). It runs git hardened (no pager, hooks, file-system monitor, credential helper, replace refs, graft file, commit-graph file, transport of any protocol or lazy fetch, a bounded time, and no search above the named directory, whose links and `..` parts are resolved first) and never fetches. It finds git the way Rust's standard library does, which on Windows has not searched the current directory since Rust 1.58: a `git.exe` in the repository under check, or in the directory the doctor runs from, is never run, while a `git.exe` beside `engram.exe` is found before PATH and shares the install directory's trust. A git call that outlasts its time bound is stopped, and one whose output stays open past the bound is abandoned; neither gives an answer. On Windows `git.exe` is usually a launcher, and the real git it started may run on, but the doctor does not wait for it. It names an absent commit, a commit off the branch, a remote-tracking ref not present locally, or a stored landing that fails the shape every write checks (never handed to git), and reports a failing git call, such as one in a damaged repository, as unverifiable rather than as an answer, as it does a commit not found on the branch of a shallow repository, whose cut history may hold it. ## Removed pre-release scaffolding

The obsolete whole-task advisory claim API/tables, standalone report/barrier
types, and unwired dummy publication adapter/table are removed. Active
control sessions bind directly to shared anchors by project and external
reference; the compatibility-task lifecycle and tables are removed. Fenced
local-work claims remain. Resource leases, host obligation waiver, and the
finalizer turn purpose/phase are removed. The operator waiver command remains;
acceptance-binding revision still resolves obsolete bound obligations. Turn
grants no longer carry a delivery page, recovery turns are removed, and the
context-packet assembly that only the grant's page used is removed with it.
Stored grants that carried a page still decode and audit clean.
