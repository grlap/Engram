# Shipped Today

This page inventories only behavior present in the installed build. It excludes
planned, target, and deferred capabilities; those belong in the
[roadmap](roadmap.md), not in this table.

| Surface | Installed behavior | Contract |
| --- | --- | --- |
| Explicit memory text | CLI `remember` accepts either positional text or `--text TEXT`, with the same key and revision options. Supplying both forms or neither is refused. | [Agent words](features/cli-and-mcp.md#using-engram-as-an-agent) |
| BOM-prefixed JSON files | JSON `@path` inputs accept one leading UTF-8 BOM. Raw input limits include the BOM bytes; inline JSON and string contents are unchanged. | [CLI input](features/cli-and-mcp.md#host-and-operator-cli) |
| Short orientation | Compact `next` and `next --peek` place held and assigned work before at most five ready candidates, each with its projected readiness reason. `ready_more` and `ready_next` preserve navigation through `ls --ready` after byte fitting; expired cursors offer a fresh ready listing. No delivery or memory-recovery semantics change. | [Agent orientation](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Atomic authored plans | `work core propose` with `kind: "plan"` creates up to 256 new tasks under one root or across a forest, with at most 255 open descendants per root and 1024 explicit prerequisites, in one graph transaction. The descendant limit also applies to ordinary planning and graph restoration. One final whole-project cycle scan precedes commit. Exact retries recover the full key-to-ref mapping under a separate 64 KiB compact JSON result budget. Typed plans are bounded to 1 MiB; raw CLI `core` propose, update, complete, and handoff input is 2 MiB of transport bytes (including whitespace and a leading `@file` BOM), not a guarantee that every semantically valid payload fits. Focus, live claims, ordinary decomposition's per-call limit and agent-response limits are unchanged. | [Atomic work plans](features/atomic-work-plan.md) |
| Explicit source intake | File preview/apply creates one imported root from an authored local draft. Exact source lookup distinguishes its citation from later source-change notices. Refresh never patches local work; show counts notices and planning recovery retains their provenance. | [Source intake](features/source-intake.md) |
| Work display attribution | Terse show, windows/detail, compact holders, statuses, reminders and changes use stable project-scoped peer pseudonyms. Same-actor peers are not `you`. Labels do not resolve as identity aliases; low-entropy inputs remain guessable. Canonical audit and rich verbose metadata remain raw. | [Output contract](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Non-advancing orientation | `next --peek` / MCP `peek: true` reads held, ready, discovery, changes and the memory signal in one snapshot without staging, acknowledgement, focus changes or process-default registration. It opens only an established store. Bounded previews repeat from confirmed delivery; non-advancement and memory navigation are never shed. Ordinary `next` remains advancing. | [Peek contract](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Criterion evidence disclosure | Successful `done` and completed native `show` name the count and one-based frozen-seal positions with "no evidence linked to this criterion", with exact bounded omissions. Work-level notes and gates do not manufacture criterion links; absence does not refuse completion. Old seal bindings remain unchanged. | [Completion disclosure](features/local-work-system.md#audited-waivers-and-model-autonomy) |
| Explicit criterion links | `done --link POSITION=LOCATOR --link-basis N` (MCP `links`/`link_basis`) reuses existing current-run evidence. The required read basis refuses any work revision drift; sealed readback names author-linked evidence, not verification, while unlinked criteria remain visible. Specific refusals distinguish non-member records without widening evidence membership. | [Agent link contract](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Explicit reads | Targeted agent `show` (including notes, history and detail), catalog/search and project-memory reads preserve focus, claims and staged delivery, and defer process-default session registration until the first stateful operation. Established WAL-store reads remain available under a peer's held writer. Reading another item does not redirect later bare writes; target mutations explicitly. | [Agent read contract](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Required-child rejection | `update CHILD --reject REASON` atomically cancels an admitted required child and records its open parent's attributed waiver. Same-session keyless intent retries recover both effects only for the unchanged cancelled child; completed work retains late-finding guidance and other unsupported shapes offer typed conditional cancel/waive guidance. Successful `done` discloses the seal-bound count of criteria asserted satisfied and that completion changed no criterion. | [Agent contract](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Coordination status and linkage | `note --status` captures owner-qualified duty or a separate peer observation. Compact `next` shares proven same-capture status/note context per item, with explicit status body omissions and detail navigation; clipped status projections require a full-note read before acting on approval/STOP conditions. Ordinary note heads retain `show --notes` navigation. `next` and `show` distinguish the same actor across sessions without exposing principals or transferring claims. Audited external references appear in readers, catalog search, and graph snapshots; `update --clear-external` removes them through an ordinary revision. | [Agent resume](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Output economy | Add/claim/gate/note/done share one compact item/result envelope with live holder/expiry, actionable counts, refusal/omission signals and one `full_detail` read. Note/history continuation pages replace repeated item context with a compact header; all windows report their active byte ceiling and reflected read cut. | [Agent receipts](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Parent child summary | Safe parent `show` always separates required children still owed from open optional follow-ups with exact totals, bounded refs, exact omissions and scoped continuation-capable listing commands; optional children never block completion. | [Agent detail](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Parent context | Full child `show` names its direct parent, title and lifecycle, states the child's own required/optional requirement, and offers `show PARENT` through output trimming. Roots say `parent: root` and omit parent fields and child requirement. | [Agent detail](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Listing continuation | Bounded CLI/MCP lists carry exact totals, active limit/byte ceiling, and same-filter continuation from the final emitted row. Stale cursors refuse explicitly; direct-parent optional/required filters enumerate scoped children. | [Agent listing](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Detached follow-ups | `update CHILD --detach "why"` creates an independent root and supersedes an eligible child under a terminal ancestor atomically, preserving old claims/fences and frozen parent history. A still-open root's live contributor accounting is reconciled as with cancellation. `show CHILD` and `ls --blocked` expose the remedy; `next` does so when the child is already focused. Reading the child does not establish that focus. | [Detached follow-ups](features/local-work-system.md#gates-prerequisites-supersession-and-project-memories) |
| Resume discovery | CLI/MCP `next` shows bounded assignment and this session's recent participation, with own-note summaries, holder words, dense ordering, and exact omitted counts; no claim or review obligation is inferred. | [Agent-native protocol](features/local-work-system.md#agent-native-protocol) |
| Detached origin | `show SUCCESSOR` identifies its locally retained detach source and reason and offers `show ORIGINAL`; notes and gate credit stay on the source. | [Detached follow-ups](features/local-work-system.md#gates-prerequisites-supersession-and-project-memories) |
| Agent words | The CLI ships thirteen work words (`next`, `ls`, `show`, `add`, `claim`, `update`, `gate`, `note`, `done`, `handoff`, `remember`, `memories`, and `forget`), and MCP exposes the same words plus `search`. | [Using Engram as an agent](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Remaining optional children | Successful `done` names bounded direct open optional children with exact omitted counts, admitted detach commands or resolve-first guidance, and parent navigation. Completion succeeds unchanged and no follow-up is mutated automatically. | [Lifecycle and readiness](features/local-work-system.md#lifecycle-and-derived-readiness) |
| Required-child successor resolution | An immediate Completed Required sibling in the same parent/execution resolves a superseded requirement through its native seal, with immutable `resolved_by_successor` accounting and no synthesized waiver. `done`, `show`, and all-lifecycle listing agree; other successor shapes remain owed with their state and reason. Existing seals never change. | [Supersession](features/local-work-system.md#gates-prerequisites-supersession-and-project-memories) |
| Full contract detail | Safe CLI/MCP `show` retains each displayed acceptance criterion and detach reason in full. Final fitting may omit whole criteria or other entries with exact counts; on completed work, frozen criterion disclosure and criteria text compete for the byte budget. Retained contract text is never truncated internally or given an ellipsis; list/core summaries keep their existing bounds. | [Using Engram as an agent](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Planning words | `add --under REF [--optional]` creates required or optional children; peers may propose only optional children beneath foreign-held parents without changing holder authority. Repeatable `add --note TEXT` records initial observations atomically. `update REF` exposes `--after OTHER`, `--drop-after OTHER`, `--waive CHILD --reason`, `--supersede-with NEW --reason`, `--cancel REASON`, `--blocked WHY`, and `--unblock`; repeatable `--accept` replaces the whole acceptance list through an audited field revision. | [Graph invariants](features/local-work-system.md#graph-invariants) |
| Structured receipts | `--json` on any word prints its structured receipt, a successful mutation under a process-defaulted session adds `effective_session_id`, and `show`, `next`, or `done` reports typed count and byte-budget omissions, including the `omissions` array, instead of silently truncating. `ls` returns exact filtered `total` and `omitted` counts and a budgeted truncation hint. | [Using Engram as an agent](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Runtime binding | `ENGRAM_HOME` selects host-local data, `ENGRAM_ACTOR_ID` and `ENGRAM_SESSION_ID` supply asserted principals, optional `ENGRAM_ACTOR_CONTEXT` adds bounded attribution, generated process-default ids have seven-day reuse, and each newly created session reclaims at most 64 inactive predecessors. | [Host configuration](features/cli-and-mcp.md#host-configuration) |
| Project selection refusal | Every CLI work word refuses missing, unreadable or empty project files with `project_resolution_failed`, the searched directory, cwd-based selection rule and explicit `--project-file` recovery guidance in text/JSON. No project or store is created or selected implicitly. | [Host and operator CLI](features/cli-and-mcp.md#host-and-operator-cli) |
| Build diagnostics | `--version`, CLI/MCP `next`, and doctor share a runtime-derived build fingerprint; doctor includes executable/schema components and typed JSON open refusals without implicit repair. | [Build identity and doctor refusals](features/cli-and-mcp.md#build-identity-and-doctor-refusals) |
| Host tiers | The base tier injects the agent words and remains advisory, while a `turn_gated` tier must use the host-private control channel and withhold every prompt until Engram grants and begins the turn. | [Control assurance](features/behavioral-control-plane.md#control-assurance) |
| Canonical store | One host-local SQLite database per stable project id is the canonical source of truth shared by concurrent sessions and worktrees. | [SQLite store](features/sqlite-store.md) |
| Store version | The prerelease store uses schema marker 1, and ordinary open refuses an established store written by a different build before mutation. There is no in-place store upgrade; projection repair cannot convert a different durable schema. | [Canonical-bytes contract](features/sqlite-store.md#canonical-bytes-contract) |
| Projection repair | `engram doctor --repair-projections` explicitly rebuilds only declared indexes, triggers, and FTS from verified durable rows, never missing durable state or canonical objects. | [Rebuildable and durable projections](features/sqlite-store.md#rebuildable-and-durable-projections) |
| Work-graph snapshot | Operator-only `engram graph save` writes one deterministic planning/history snapshot at a coherent work-and-memory cut, redacts restricted project-memory bodies by default, requires an audited reason to widen them, and commits a doctor-visible disclosure attempt before publishing without replacement. `engram graph load FILE [--dry-run]` validates the complete file and recreates its planning graph, inert history, and keyed memories atomically in an empty project store, with a separate doctor-visible load audit. | [Work-graph snapshot](features/work-graph-snapshot.md) |
| Project memories | `remember --revise` appends attributed versions under one permanent key, with optional expected-revision conflict checks and replay. `memories` reads the current version or bounded history. Snapshots preserve live histories; `forget` retires the key permanently and exports no version bodies. | [Gates, prerequisites, supersession, and project memories](features/local-work-system.md#gates-prerequisites-supersession-and-project-memories) |
| Work evidence | Holder notes checkpoint execution; non-holder notes on open or blocked work are marked project/root observations with no run credit. After completion any project-bound session may append `note` or `gate` as a late finding outside the frozen seal. Peer changes distinguish sessions even when they share an actor. | [Gates, prerequisites, supersession, and project memories](features/local-work-system.md#gates-prerequisites-supersession-and-project-memories) |
| Claim renewal | `claim REF [--ttl SECONDS]` renews the holder's live claim without changing its identity or fence or shortening expiry; receipts expose the expiry. | [Claim and resource lease](features/local-work-system.md#claim-and-resource-lease) |
| Explicit note/history windows and detail | `show REF --notes` selects newest notes/observations, excluding structured gates by default; `--notes --gates` includes them with exact item-wide family counts. Notes and `--history` render each window chronologically and continue through older records with exact omissions inside 12 KiB. `--note LOCATOR` returns complete detail independently of the gate filter and beyond that ceiling when needed; new note bodies have a 64 KiB UTF-8 write limit while retained larger bodies remain readable. | [Using Engram as an agent](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Handoff | `handoff` ships offer, accept, and cancel actions backed by the current claim and checkpoint-coupled transfer rules. | [Using Engram as an agent](features/cli-and-mcp.md#using-engram-as-an-agent) |
| Host integration | The installed words a host needs for the advisory base tier: `engram init --required-assurance advisory --authorized-by <operator> --reason "<why>"` once per project on each host (a plain `init` defaults a fresh store to `turn_gated` and preserves an existing store's policy), one `engram mcp --actor-id … --session-id …` child per session, and `engram work next --peek` injected at the next dispatched prompt after session start or compaction, not an immediate runtime continuation. | [Host checklist](host-checklist.md) |
| Unused root probe | Agent work words, MCP startup, graph, backup, restore and import do not write a project-root filesystem-identity probe marker. Path-bearing host commands (`init`, `doctor`, `control`, `authority`, `control-policy`) still resolve identity by flag or probe. Ordinary store and file I/O on those agent paths is unchanged. | [Host path identity](features/cli-and-mcp.md#host-integration) |
| CLI error line policy | Every `anyhow` `Err` from `run_cli` prints framed `error: <Display cause>` per cause on stderr (exit 1), in any output mode, including `--json` and core input/argument errors. Work text refusals frame message and reminder lines; `next` commands keep safe quoted spacing. The host-path probe `WARNING` uses the same line policy. The same prefix-free helpers also frame success-receipt / MCP text; they are not a store or JSON sanitizer. Clap help/parser stay on clap's writer; `--version` is a custom DisplayVersion build printer, not that renderer. Panics stay outside. Structured JSON receipts and refusal envelopes keep source projections without terminal sanitization. Project-file `terminal_detail` is a separate, unchanged framer. | [Agent words](features/cli-and-mcp.md#using-engram-as-an-agent) |
